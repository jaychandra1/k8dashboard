## 0. Before you start: the package

1. ✏️ **Package identity — set as variables, never committed.** Go to Partner Center → your app → **Product management → Product identity**. Add two of its values as GitHub repository variables (Settings → Secrets and variables → Actions → **Variables**). For a local build, set them as environment variables instead.
   - `Package/Identity/Name` → `MS_STORE_IDENTITY_NAME`
   - `Package/Identity/Publisher` → `MS_STORE_PUBLISHER`

   `package.json` keeps placeholders for these two, and the build passes the variables to electron-builder (`scripts/store-identity.mjs`). The third value, `Package/Properties/PublisherDisplayName`, is the account's public publisher name, **JDG Initiates**; it's in `package.json` (`build.appx.publisherDisplayName`). Partner Center rejects a package whose identity or display name doesn't match exactly.
2. **Build the MSIX after setting them.** Get it either way:
   - Tag a release, then download the **`store-k8board-windows`** artifact from the **Build & Release** run's summary page. It's a zip containing `K8Board-windows-store.msix`, kept for 30 days.
   - Or run `npm run dist:store` on Windows; it writes `release/K8Board-windows-store.msix`.
3. The package declares `runFullTrust`, so section 7 needs the justification text given there. Packaged Win32 apps always declare it.

### Description (2,991 / 10,000 characters; plain text, no URLs or HTML)

```text
K8Board puts your Kubernetes clusters in one window. Point it at your kubeconfig, or sign in to AWS or Azure from the app, and get live dashboards, every workload, logs and terminals without memorising kubectl commands. Everything runs on your PC: there is no K8Board account, no K8Board server and no telemetry.

EXPLORE
• A live cluster dashboard with node and pod health and capacity at a glance.
• Every workload type (Pods, Deployments, StatefulSets, DaemonSets, Jobs, CronJobs, Services and more) with live CPU and memory, container status and links between related resources.
• An interactive topology graph of a namespace, Custom Resources, Helm releases with their values and manifests, and cluster events.

OPERATE
• Stream and search logs per container or merged, with timestamps, regular-expression search and download.
• Open a shell in a container and port-forward a Service to your PC (these two features need kubectl on your PATH).
• Scale, restart and delete with confirmation, and create or update resources from YAML with a server-side validation (dry run) first.

CLOUD CLUSTERS WITHOUT A CLI
• Sign in to AWS IAM Identity Center (SSO) or Azure in your browser, discover your EKS and AKS clusters across accounts and subscriptions, and add them to your kubeconfig. Bundled sign-in helpers mean you don't need the AWS CLI, the Azure CLI or kubelogin to use them.
• See which clusters share an AWS sign-in, sign out, and give production clusters a sign-in of their own.
• Clusters from GKE, on-premises, kind, minikube and Docker Desktop work straight from your existing kubeconfig.

SECURITY CENTER
• Find image vulnerabilities (CVEs), configuration issues, risky RBAC roles and exposed secrets, from Trivy Operator reports in the cluster or by scanning images on your PC with the open-source Trivy scanner, which K8Board downloads on first use (pinned version, checksum-verified).
• Export a report as PDF, HTML or CSV to share with the team that owns the workload.

ARGO CD
• Detected automatically: a GitOps dashboard, application resource trees, ApplicationSets and Projects, with Sync, Refresh and Rollback.

AI, BRING YOUR OWN
• An optional, read-only assistant that answers questions about your cluster using the OpenAI-compatible model endpoint you configure. Secret values are redacted before anything is sent.
• Open AI coding agents you already have installed (such as Claude Code, GitHub Copilot CLI, Gemini CLI, Codex or opencode) in a docked terminal.
• A built-in MCP server so AI agents can inspect your cluster. Write access is off by default.

PRIVATE BY DESIGN
K8Board talks directly to your clusters and to the cloud and AI services you choose. Your credentials stay on your PC, in the standard kubeconfig, AWS and Azure locations. Updates come from the Microsoft Store.

Requirements: access to a Kubernetes cluster (a kubeconfig file, or an AWS or Azure account with EKS or AKS clusters). kubectl is needed only for pod terminals and port-forwarding.
```

**Publishing hold.** For the first release, choose **Don't publish this submission until I select Publish now**. You can then check the live listing's text and images before customers see them. Use the default for later updates.

**Notes for certification** (✏️ add the date):

```text
Thank you for reviewing K8Board.

K8Board is a desktop client for Kubernetes clusters. It needs no account with us and has no in-app purchases.

To show its features it needs access to a Kubernetes cluster through a kubeconfig file (%USERPROFILE%\.kube\config). Without one, it starts and shows how to add a cluster (Amazon EKS, Azure AKS or a kubeconfig file). That is the expected first-run screen, not an error.

A quick test cluster on Windows: Docker Desktop > Settings > Kubernetes > Enable Kubernetes, or kind ("kind create cluster"). Then start K8Board; the cluster appears in the cluster picker at the top left.

Features that need something extra:
- Pod terminal and port-forward: kubectl on PATH.
- AI assistant: an OpenAI-compatible endpoint the user configures in Preferences > AI Assistant.
- Security Center image scanning: on first use, and only when the user starts a scan, K8Board downloads the open-source Trivy scanner (pinned version 0.76.2) from its official GitHub release and verifies its SHA-256 checksum before use.

Updates: in the Store edition, Help > Check for Updates never downloads or installs anything; when a newer version exists it offers to open the Microsoft Store.

The package declares the app execution alias k8board.exe. K8Board writes it into kubeconfig as the credential helper for EKS and AKS clusters, so kubectl can authenticate from any terminal.

Notes entered on: <date of submission>
```

## 7. Restricted capabilities: runFullTrust

Paste this into Submission options → **Restricted capabilities**:

```text
K8Board is a Win32 desktop application (Electron) packaged as MSIX, so it needs runFullTrust for its Windows.FullTrustApplication entry point. It also needs a full-trust process for what it does on the user's behalf: it runs a local backend bound to 127.0.0.1; reads and writes the user's kubeconfig (%USERPROFILE%\.kube) and AWS and Azure configuration files; connects to the user's Kubernetes API servers; starts kubectl, Helm and the user's installed command-line AI agents in pseudo-terminals (ConPTY); and acts as the credential helper (through the k8board.exe app execution alias) that kubectl runs to get cluster tokens. None of this is possible from an AppContainer.
```

Approval normally carries over to later updates unless the package declares new capabilities.

## Things that can fail certification, and the answer

- **"The app looks empty."** Testers may have no cluster. The notes explain the first-run screen and give a two-minute way to get a test cluster.
- **Downloaded code.** Trivy is downloaded only when the user starts an image scan, from Trivy's official release, at a pinned version, and checksum-verified. The description and the notes both say so.
- **Self-updating.** The Store edition never installs updates itself; it sends people to the Store.
- **Privacy policy.** `https://k8dashboard.in/privacy` must be online when you submit. It already covers the Microsoft Store edition.
